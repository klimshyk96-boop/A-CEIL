# Client calculator — first test

## Width-aware films and profile variants

Film choices now come from `ACEIL_COLOR_CATALOG_BY_SERIES` and current `ACEILGetFilmPricing`, with matching live room rows taking precedence for their own colour/width. The owner sees film families (manufacturer, series, texture, colour) rather than individual roll SKUs. M303/L303/S303 families with positive configured prices are offered even if the room has no live film item. Inactive zero-priced series are omitted. The public snapshot contains only the selected families' nominal width, maximum working span and retail rate; the rest of the catalogue stays private. Existing stored width-SKU selections map back to their family.

For a rectangle, required span is `min(width,length)`, matching A·CEIL's `getRequiredFilmWidthMeters()`. Area/perimeter entry asks separately for cross width and does not infer it from area. Pick the smallest nominal roll whose recorded working span fits, then use its own m² rate. Boundaries use a tiny numeric tolerance; missing/beyond-range spans block the estimate. No universal stretch factor is invented. Old flat-price links remain readable with an explicit warning that width tariffs were not supplied; owners must save a new snapshot to publish the rules.

Basic profiles expose aluminium/PVC; shadow and floating expose white/black. Availability and prices come from selected rows, not fabricated alternatives. Retail metadata retains material/colour and, where a unique matching corner source exists, its colour-specific corner rate. Otherwise the explicitly selected shared family corner rate remains in use. The public UI separates room, film, profile and extras, explains selected roll/rate, and keeps a compact total visible on mobile. `tests/client-film-width.test.cjs` checks working-span thresholds, rotation, over-wide rooms, manual width, film availability with no room items, material/colour price differences, and persisted width.

Public entry: `/calculator/`. `?demo=1` opens an explicitly labelled demo with illustrative rates; it is not a company offer.

In the test editor open **Номенклатура → ⚙ → Калькулятор для клієнта**. The first visit asks for exact retail catalogue rows and optional minimum order. Save once; later visits show the reusable link and copy button, with price settings collapsed under **Змінити прайс**. The published retail snapshot and row mapping are stored under the signed-in user's local preset key. Updating nomenclature does not silently alter previously shared snapshots; save the updated price selection explicitly.

Film, classic profile and classic corners are required. A unique matching source is preselected; ambiguous matches require a choice. Special profiles require their corner row; floating additionally requires LED. A zero-price corner row can represent corners included in the profile rate. Only allowlisted names/prices are exported, with a date; no cost prices, other catalogue entries, auth credentials, projects or client contacts are included. Client links use `https://a-ceil.pp.ua/calculator/`; preview-host links are separately labelled **Перевірити на тесті**. The four standalone public files can be released to main without merging the test editor/report changes.

The owner may select multiple retail rows per category in **Додаткові варіанти для клієнта**. The main row is the default; checkboxes add films, profiles, inserts, fixtures, cornices and light lines to the public assortment. Selected rows are remembered alongside the price snapshot and shown under **Збережений асортимент і ціни**. Source prices are edited in nomenclature; publishing a new snapshot reads current prices. The chosen family corner rate remains the fallback; a unique matching colour-specific rate is exported with its profile variant. Only selected names, retail rates and calculator-local option IDs enter the public configuration. Individual variants and light-line length round-trip through client links; unknown selected option IDs block pricing.

Client inputs: a rectangle in metres, or measured area/perimeter/corner count. No arbitrary contour drawing in this iteration. The rectangle diagram uses entered proportions; area/perimeter mode does not invent a floor plan. Dimensions, integer counts, impossible area/perimeter combinations and missing selected rates block the estimate. Cornice and light lines are additive retail rows, without subtracting profile length; a light line uses its selected per-metre price and entered total length. Complex walls, film width, joins and extra installation work require a professional check.

The URL fragment stores the retail configuration and optional room snapshot. A share link can be reopened and edited on another device without login; copying an updated calculation creates a new snapshot. Old links retain old rates. URL data is editable and is not a binding or authenticated quote. No backend record or anonymous write access is introduced.

Names/phone/comment are only in the outgoing message, not in the URL or browser draft. The client explicitly chooses the receiving app and recipient in the phone's share sheet. Fallback: copy the message and send it manually. The UI never claims a lead was saved to an inbox. Automatic lead intake, short permanent URLs and drawing arbitrary contours are follow-up work.

Validation: `tests/client-calculator.test.cjs` covers formulas, minimum, alternate profiles, LED, invalid input, owner price export, contact exclusion, URL round trip, hash changes, malformed links, text injection, disabled missing-rate choices, and mobile/desktop layouts. It is included in the deploy gate.
