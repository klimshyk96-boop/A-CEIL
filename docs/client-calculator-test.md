# Client calculator: three-step test
## Owner assortment checklist test (21 October 2026)
Owner settings now show the full merged nomenclature as categorized checkbox rows, including previously unrecognized products and items without prices. Search and All/Selected filters preserve checks. Unknown items require an explicit category compatible with their unit before saving. Corner categories accept one rate each; profiles use their related corner and LED rates automatically. Existing v4 primary/extra choices migrate without adding unselected products; v5 stores explicit item-to-category choices. Price-less products remain quote-required. Unchecked film series are removed from the exported shared-palette tariffs. Generated film families combine width rows; a selected series retains its full shared colour palette.

The link controls are collapsed when opening saved settings; after saving, the ready link is shown. Only selected allowlisted retail product data is exported. Client options allow up to 60 per category and 120 overall; the existing 24,000-character snapshot-link limit still applies. client-assortment-checklist.test.cjs covers migration, unknown rows, category validation, search, filtering, thirteen cornice models, stable prices, persistence, removal and two viewport sizes. This change is test-only until approved.

The test branch replaces the long client form with Room → Ceiling → Extras. Phone totals remain visible; the detailed estimate and outgoing message open in a native dialog. The desktop also has a compact estimate sidebar. Fields appear only for selected extras; removing a card clears its charge. No fixtures are selected in a new calculation.

Room input supports rectangles, measured area/perimeter, and a contour drawn by successive taps on a 25 cm grid. Contours store metric coordinates, not screenshot pixels. Area uses the shoelace formula; perimeter uses Euclidean segment lengths; each vertex is a corner. Up to 24 vertices are supported. Duplicate/short edges, collinear vertices, self-intersections, nonfinite/out-of-bounds points and degenerate polygons block pricing. The coordinate editor allows more precise measurements. Undo reopens a closed contour, then removes points; clearing starts again. The plan preserves one scale on both axes. This is a preliminary straight-wall contour, not the editor's curve/diagonal solver.

Film series are Classic, Premium and Kralton. The smallest available nominal roll whose recorded working span fits is selected using the shorter rectangle dimension or the contour's shorter axis-aligned bounding dimension. This is a preliminary fit, not a cutting/seam plan or minimum rotated bounding box. Area/perimeter mode requires separate measured cross width. Unknown tariffs remain explicitly quote-required; they never become free, and the partial known sum is never shown as a complete price. Profiles retain aluminium/PVC or white/black choices.

Owner settings are under Номенклатура → ⚙ → Калькулятор для клієнта. Five collapsed groups contain relevant product categories rather than every item sharing a measurement unit. Explicit saved mappings remain available for compatibility. Only selected retail names/rates and allowlisted width/material/colour metadata are published. Option IDs derive from the original selected product identity and stay stable across reordering. Source prices are edited in nomenclature. A selected corner row supplies the fallback profile corner rate; exact colour corner matches take precedence. Cornices are additive and do not subtract profile length.

## Snapshot and cloud links
Old v1 hash links are still supported and retain their published retail snapshot. Test demo prices are explicitly labelled. New cloud links use /calculator/?c=<random32hex>. They load the latest published retail config with no-store and a 10 second timeout. A saved cloud calculation appends only client state to the fragment; it does not freeze the catalogue. Missing/failed cloud reads show unavailable and never substitute demo or old browser prices. Contact information is only part of the message sent through a user-selected sharing app, never the URL or browser draft. There is no automatic lead inbox.

The adapter and migration supabase/migrations/20261021090000_client_calculators.sql are prepared. **The migration has not been applied to the live database.** A read-only endpoint check returned HTTP 404 / PGRST202. Until an administrator applies it, the owner sees a clear unavailable message when publishing; the local draft remains saved. No DB admin integration or credentials are available in this session. The main/public calculator is unchanged during this test.

After applying the migration, authenticated active owners publish one catalogue each through aceil_save_client_calculator. Upsert by user_id retains the same random token. Anonymous callers can only read the explicit published config by token; direct table access and anonymous writes are revoked. Existing projects, nomenclature and report tables are untouched. Owner publication has a timeout and reports unconfirmed writes honestly.

## Full shared film palette and nomenclature cornices
The client now reads the existing js/nomenclature/165-aceil-color-catalog.js registry directly. Premium, Classic and Kralton expose every registered colour, with an all/matte/gloss/satin filter and search by code/name. No new colour names or swatch RGB values are invented. The compact published config carries allowlisted per-series/texture width tariffs and only sparse colour/width price exceptions; it does not duplicate hundreds of colour entries into the URL. filmCode and filmSeriesId persist in client state. Missing prices remain quote-required; colours narrower than the required room span remain in the palette but block the estimate if selected. Legacy flat-price film options continue working until a catalogue colour is selected.

Owner export reads both the master nomenclature cache and runtime items, using master catalogue prices over stale room copies with the same item ID. Cornices match metre units and name/source/type metadata. Colour comes from explicit colour/sourceVariant, source suffixes, or unambiguous name/source text. UNO/ceilingcornice:uno maps to single-row; wide takes precedence when explicitly named. Known metre prices replace quote templates for their exact type/colour. Unknown or ambiguous types/colours are not assigned made-up prices. The new fixture test verifies all seven variants with different real-input retail rates, including master-only items and source-only UNO colours.

After source price changes, save the owner catalogue again to regenerate a snapshot or publish updated cloud tariffs. Demo remains illustrative; it does not read a private signed-in owner's nomenclature. The live cloud migration is still pending.
