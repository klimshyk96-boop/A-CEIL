# A·CEIL · Безвставочний профіль і два окремі КП (12.11.2026)

## Номенклатура
У наявній базі вже є дві позиції, їхні ціни **не змінюємо**:
- `Безвставочний металевий`, `350 грн/м` у поточному каталозі → `noinsert_profile`.
- `Фіксація кутів - безвставочний профіль`, `200 грн` у поточному каталозі → `noinsert_corners`, одиниця **шт**, навіть якщо старе поле `unit` у каталозі було `м`.
Ціни беруться з чинної номенклатури користувача; код **не встановлює** глобальних або фіксованих тарифів.

Поведінка відповідає тіньовому профілю:
1. Для повного периметра безвставочного профілю базовий H = 0 м, маскувальна вставка = 0 м, базові кути = 0 шт, кути безвставочного = усі кути кімнати.
2. Для часткового ручного введення `L` м профілю: H = `max(0,P-L)` м, вставка = `max(0,P-L)` м; **без розмітки конкретних стін/кутів** програма не приписує спеціальних кутів довільно (як і для тіньового).
3. Коли спеціальний профіль позначено на кресленні, кути розподіляються за геометрією цих стін.
4. Обнулення спеціального профілю повертає H, вставку й звичайні кути.
5. Окремі елементи на кшталт карнизів, треків і світлових ліній не змінюються.

## Обов'язковий сценарій двох КП
У списку проєктів є **«⧉ 2 КП»**:
1. Спочатку оригінал має бути повністю синхронізований з Supabase.
2. Натискання створює окремий `projects`-рядок з новим ID, з повною геометрією, кімнатами та цінами; початковий проєкт не редагується.
3. Копія названа `<Оригінал> — Безвставочний`; старі report-токени, посилання й внутрішні варіанти звітів НЕ копіюються.
4. У копії відкривають креслення, змінюють профіль через номенклатуру, зберігають і формують власний клієнтський звіт.
5. Оригінал має свій звіт, копія — інший, кожен публікується чинним `aceil_publish_report_snapshot`; зв'язок копії з оригіналом зберігається як `comparisonSourceId` у власному `state`.
6. Кнопка **«🔗 2 звіти»** показує обидва посилання. Копіювання двох разом розблоковується лише після публікації **двох різних URL**. Функція не публікує завідомо неготове креслення автоматично.

## Безпека
- Не видаляти або не змінювати оригінал заради варіанта.
- Не створювати посилання до підтвердження хмарного збереження нової копії.
- Не вважати двома КП два URL одного проєкту: копія має окремий Supabase ID.
- Не переносити `report_token`, `report_published_at`, `calcLinks` і `_aceilVariantsShadow` між проєктами.
- Не підміняти контурні кути трековими/карнизними.
